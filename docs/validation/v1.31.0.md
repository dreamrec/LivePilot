# LivePilot 1.31.0 validation

The release keeps 474 tools across 57 domains and extends existing device
and sound-design operations.

## Native control smoke test

On 12 November 2026, the MCP tool implementations exercised the updated
Remote Script in Ableton Live 12.4.7 on macOS. The original stopped Set had
four tracks. Each pass created one named, muted test track, loaded a stock
Instrument Rack and a nested Wavetable, then deleted only that test track.
The final track count and stopped transport matched the baseline.

Verified operations:

- Discover a child device path and session-local device identity.
- Read nested parameter ranges and display values.
- Set Osc 1 Pos to 0.33 and read back 0.3300000131 (33 percent).
- Reject an incorrect expected_device_id before writing.
- Enumerate the actual Wavetable source enum and visible target rows.
- Read and write an existing modulation row by target index.
- Add Osc 1 Transp as a new matrix row using its DeviceParameter object.
- Resolve that row's display name Osc 1 Pitch and underlying parameter name
  Osc 1 Transp without assuming that they match.
- Set LFO 1 modulation to 0.23 and read back 0.2300000042.
- Read the complete non-zero matrix, including pre-existing MIDI routes.

One read reconnected after the socket closed during a UI transition; only
the read was retried. Cleanup confirmed ownership and the session token
before deleting the test track. No audio was played during these control
checks. They establish parameter/control behavior, not an artistic benefit.

## Wavetable API provenance

The installed and staged Ableton factory Push2 scripts agree on:

- add_parameter_to_modulation_matrix(DeviceParameter) returns a target index.
- get_modulation_value(target_index, source_enum).
- set_modulation_value(target_index, source_enum, amount).
- Native amount range -1 to 1; the UI multiplies by 100 for display.

The implementation resolves Live.WavetableDevice.ModulationSource enum
members rather than assuming their numeric order. Factory ModMatrixParameter
code-object SHA-256 in both inspected bundles:
7b9f2a075e1016452105bbd1a05b63d1fef4db3ff14861762a8cfd9da9423080.

The [official Wavetable reference](https://docs.cycling74.com/apiref/lom/wavetabledevice/)
also documents parameter-object insertion and target/source order. The
factory setter establishes the third amount argument omitted from that
reference's parameter listing.

## Compatibility limits

At the time of the live checks, 12.4.16 was downloaded into the staged update
bundle while the MCP session reported 12.4.7. No 12.4.16 runtime qualification
is claimed here. Per-clip scale properties documented in 12.4.15 remain
object-probed, with explicit unsupported errors on older builds. Their
setter's scale-name fallback and missing-property behavior have automated
regressions; the new clip API was not exercised live in this check.

Nested path resolution supports at most eight explicit rack-chain/device
hops. Device identity guards are local to the loaded Set and must be read
again after a session change. Two-level resolution and rejected stale or
malformed paths are covered by automated tests; the live rack test used one
chain hop. Creation, deletion, routing, and automation APIs have not been
extended to arbitrary nested targets by this release.

The sound-design changes label structural hypotheses and remove unsupported
quality penalties. They do not measure spectral flux or modulation depth.

## Distributed package checks

Both npm and MCPB archives are extracted outside the source checkout during
validation. Their runtimes import as 1.31.0 with 474 tools. Synthetic gzip/XML
ALS, ADG, and ADV fixtures are parsed through the distributed scanner entry
points, verifying that scripts/als_deep_parse.py is shipped and loadable.
No personal projects or library files are used for these package checks.

Release banners are rendered for visual inspection. Metadata checks cover
their versions and case-insensitive count labels while retaining the guard
against interpreting a year in ordinary prose as a tool count.
